# Bleak Plan 04 — Monsters and AI

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Keeper, the Brinelings and the Wisps behave exactly as the spec says, never freeze, and move smoothly.

**Architecture:** Each creature has a **brain**: a pure function `step(memory, percepts, dt) -> (memory, command)`. Brains have no engine calls and are unit-tested. A **service** gathers percepts (Perception), runs the brain at 10 Hz, and hands the command to the **Navigator**, which owns pathfinding and movement.

**Tech Stack:** PathfindingService, Humanoid `MoveTo`, raycasts, Animator.

**Spec:** `docs/spec/2026-11-13-bleak-game-design.md` sections 9.3, 10, 11, 12, 14.

Agent: **Monsters**. Every task uses the standard task cycle (master plan
section 7).

Shared shapes used by all brains:

```lua
-- type Command = {
--   move: Vector3?,            -- nil = stand still
--   speed: number,
--   face: Vector3?,            -- look at this point while standing
--   action: string?,           -- one-shot: "Wake", "Scream", "GrabStart", "GrabHit", "GrabMiss",
--                              -- "PickDrop", "Drop", "StunStart", "StunEnd", "Burn", "Die", "Teleport"
--   actionArg: any?,
-- }
-- type SeenPlayer = { userId: number, position: Vector3, distance: number, visible: boolean,
--   proximity: boolean, alive: boolean }
```

**Needs:** C9 (`DetectionMath`).

**Files:**

```lua
Perception.seePlayers(eye: Vector3, look: Vector3, ignore: {Instance}): {SeenPlayer}
Perception.hasLineOfSight(from: Vector3, to: Vector3, ignore: {Instance}): boolean

```

**Behaviour:**
- `hasLineOfSight`: one `Workspace:Raycast` with a `RaycastParams` whose filter excludes `ignore`, everything under `Workspace.Runtime`, all player characters, and all parts tagged `SeeThrough`. `RespectCanCollide = false`; collision group `Default` so that only map geometry and doors (group `Doors`, which collides with `Default`) block. True when nothing is hit.
- `seePlayers`: for every player, `alive` = status `Alive`. `visible` = within `DetectionMath.visionRange(...)` built from the player's attributes and `PlayerStateService`, inside the cone, and line of sight to the head **or** the root. `proximity` = distance ≤ 5 and line of sight. Non-alive players are returned with `visible = false`.
- `heard`: `DetectionMath.heard(distance, radius, ZoneService.floorOf(listener) == ZoneService.floorOf(event.position))`.

**Scenario checks (T2):** a player behind a closed door is not visible; behind a `SeeThrough` window is visible; with the lamp off and crouched at 15 studs is not visible; at 4 studs behind the Keeper is `proximity`.

### Task M2: Navigator

**Needs:** P3 (`DoorService.npcOpen`, `doorFor`).

**Files:**
- Create: `src/server/AI/Navigator.luau`
- Create: `src/server/AI/StuckDetector.luau` (pure)
- Test: `src/tests/unit/StuckDetector.spec.luau`

```lua
-- type AgentSpec = { radius: number, height: number, canOpenDoors: boolean, ignoresDoors: boolean,
--   doorDelay: () -> number }
Navigator.new(model: Model, spec: AgentSpec): Navigator
navigator:setGoal(position: Vector3?, speed: number, repathInterval: number)
navigator:teleport(cframe: CFrame)
navigator:status(): "Idle" | "Moving" | "Arrived" | "NoPath"
navigator:timeWithoutProgress(): number
navigator:destroy()

StuckDetector.new(): StuckState
StuckDetector.step(s: StuckState, position: Vector3, wantsToMove: boolean, dt: number): StuckState
-- s.time rises while wantsToMove and the position has moved < 1 stud from the anchor;
-- when it moves >= 1 stud the anchor becomes the new position and s.time = 0.
```

**Behaviour:**
- One `Path` per navigator: `AgentRadius`, `AgentHeight` from the spec, `AgentCanJump = false`, `AgentCanClimb = false`, `WaypointSpacing = 4`, `Costs = { LockedDoor = math.huge, Door = 2 }`. A navigator with `ignoresDoors` uses `Costs = { LockedDoor = 1, Door = 1 }`.
- `setGoal` stores the goal. A 20 Hz loop: recompute with `ComputeAsync` when the goal moved more than 3 studs since the last compute, when `repathInterval` has passed, or after `Path.Blocked` at or beyond the next waypoint. Never more than one `ComputeAsync` in flight per navigator. A result that arrives for an old goal is discarded.
- Movement: `Humanoid:MoveTo(nextWaypoint)`; advance when within 2.5 studs horizontally. Do not rely on `MoveToFinished` (it times out after 8 s). `Humanoid.WalkSpeed = speed`.
- When the last waypoint is reached and the goal is within 6 studs with line of sight, steer straight at the goal (smooth final approach during a chase).
- Doors: each tick, raycast 4 studs ahead. If it hits a part whose `doorFor` is a closed unlocked door and `canOpenDoors`, call `DoorService.npcOpen(door, position, doorDelay())` and stand still until `Open`. With `ignoresDoors`, the model's collision group already passes through doors.
- `status` is `NoPath` when the last compute failed or returned zero waypoints.
- The model's parts all have network owner `nil` (server), set once at creation.
- `teleport` pivots the model, clears the path and resets the stuck timer.

**Tests:** `StuckDetector`: 10 steps of 0.1 s at the same position with `wantsToMove` give time 1.0; moving 1.2 studs resets to 0; `wantsToMove == false` holds time at 0.

**Scenario checks (Review Focus 4):** an agent reaches a goal across two rooms and one closed door; with the door locked, `status` becomes `NoPath` within 1 s and the agent does not walk into the door; a goal inside a wall gives `NoPath`; closing a door in front of the agent makes it reopen the door, not freeze.

### Task M3: Keeper brain, base states

**Files:**
- Create: `src/server/AI/KeeperBrain.luau`
- Test: `src/tests/unit/KeeperBrain.spec.luau`

```lua
-- type KeeperPercepts = {
--   position: Vector3, players: {SeenPlayer}, noises: {Vector3}, params: StageParams,
--   stunnable: boolean,              -- DifficultyConfig stunTime > 0
--   beamDwellGained: number,         -- seconds of beam on the Keeper since the last step
--   navStatus: "Idle" | "Moving" | "Arrived" | "NoPath", noProgressTime: number,
--   wanderNodes: {Vector3}, retreatNodes: {Vector3}, dropPoints: {Vector3},
--   released: number, releaseEvent: boolean, wakeEvent: boolean,
--   brazierPosition: Vector3, random: () -> number,      -- 0..1
-- }
-- type KeeperMemory = {
--   state: KeeperState, stateTime: number, targetUserId: number?, lastSeen: Vector3?,
--   unseenTime: number, sightTimers: {[number]: number}, dwell: number, enraged: boolean,
--   stunsLeft: number, emberLeft: number, enrageIn: number?, recentNodes: {number},
--   goal: Vector3?, waitLeft: number, carryDrop: Vector3?, windup: number?, recover: number,
-- }
KeeperBrain.new(): KeeperMemory                                   -- state "Dormant"
KeeperBrain.step(m: KeeperMemory, p: KeeperPercepts, dt: number): (KeeperMemory, Command)
```

This task implements `Dormant`, `Roam`, `Investigate`, `Chase` (not enraged),
`Stunned`, `Calm`. Rules: spec 10.2, 10.4, 10.5.

**Tests** (each builds percepts with a helper `P{...}` that fills defaults; `run(m, p, seconds)` steps at dt 0.1):
- New memory is `Dormant`; with no `wakeEvent`, 10 s later still `Dormant` and the command has `move == nil`.
- `wakeEvent` gives action `"Wake"` once, then `Roam` after 4.0 s.
- `Roam` picks a wander node as the goal; on `navStatus == "Arrived"` it waits between 2 and 5 s, then picks a different node; the last 3 picks are not repeated when more than 3 nodes exist.
- `Roam` + a visible player for 0.3 s (stage 0, delay 0.40): still `Roam`. For 0.5 s: `Chase` with that target. The sight timer resets when the player stops being visible.
- `Roam` + `proximity` player: `Chase` on the same step.
- `Roam` + a noise: `Investigate` with the goal at the noise. After arriving, 8 s later `Roam`.
- `Chase` ignores noises.
- `Chase` + target not visible for 6.0 s: `Investigate` at `lastSeen`.
- `Chase` command speed equals `params.chaseSpeed`; `Roam` speed equals `params.roamSpeed`.
- `Chase` + `beamDwellGained` totalling `params.beamDwell` (1.0 at stage 0): action `"StunStart"`, state `Stunned`. Dwell decays at 1.0 per second when no beam: 0.6 s of beam, 1.0 s without, 0.6 s of beam does **not** stun.
- `Stunned` lasts `params.stunTime`, then `Calm` with action `"StunEnd"`. No movement while stunned.
- `Calm` goal is the retreat node farthest from the nearest player; a visible player during `Calm` does not cause `Chase`; after `params.calmTime` → `Roam`.
- `stunnable == false`: any amount of dwell never stuns.
- `Chase` + target `alive == false` and another visible alive player: the target switches. With none: `Investigate`.
- `Roam` can be stunned too (dwell rules apply in every state except `Dormant`, `Stunned`, `Calm`).
